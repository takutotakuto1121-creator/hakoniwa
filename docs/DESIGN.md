# hakoniwa 設計書

要件は [REQUIREMENTS.md](REQUIREMENTS.md) を参照。この文書は実装の構造と、主要な設計判断の理由を記録する。

## 1. パッケージ構成

| ターゲット | 役割 |
|---|---|
| `HakoniwaCore` | シミュレーション本体。UI に依存しない。単体テストの対象 |
| `hakoniwa-cli` | ヘッドレス実行。進化の検証、ベンチマーク、事前進化した世界の生成 |
| `Hakoniwa` | macOS アプリ。Metal 描画と SwiftUI の UI |
| `HakoniwaCoreTests` | XCTest |

外部依存はなく、Apple 標準フレームワーク(Foundation, simd, Metal, MetalKit, SwiftUI, Charts, AVFoundation)のみ。

## 2. シミュレーション

### 2.1 データ配置

生き物は**スロットのプール**(容量 `maxCreatures`)に、属性ごとの連続バッファ(SoA)として置く。
位置・速度・エネルギーなどは `UnsafeMutablePointer` の配列で、脳の結合はスロットごとに最大 192 個を固定領域に持つ。

- 参照型や可変長配列を毎 tick のループに持ち込まないため、ARC のコストがなく、保存も生のバイト列で済む。
- スロットは空きリスト(LIFO)で割り当てるので、割り当て順も決定的。
- 個体の同一性は `uid`(単調増加)で表す。UI はスロット番号ではなく uid を保持する。

### 2.2 1 tick の処理

1 tick = 1/20 秒(世界時間)。

| 段階 | 並列 | 内容 |
|---|---|---|
| 1. グリッド構築 | 逐次 | 生き物と餌の空間ハッシュを計数ソートで作り直す。近傍データ(位置・半径・色)をセル順の連続領域に複製する |
| 2. 感覚と思考 | 並列 | 各個体が自分のスロットだけに書く。衝突の押し戻し量、視覚入力、脳の評価、噛む相手と食べる餌の候補 |
| 3. 行動 | 並列 | 推進・旋回・移動、代謝コスト、成長 |
| 4. 相互作用 | 逐次 | スロット順に摂食、噛みつき、産卵。乱数を使う処理はここと段階5だけ |
| 5. 生死と環境 | 逐次 | 死亡・孵化、肉の腐敗、植物の発生、全滅時の再播種 |

**決定性**: 並列段階は「自分のスロットにだけ書く」「乱数を使わない」を守り、相互作用は固定順で処理する。
そのため結果はスレッド数に依存しない(`testDeterministicRegardlessOfThreading` で検証)。

**思考の間引き**: 感覚と脳の評価は 2 tick に 1 回(スロットごとにずらす)。思考しない tick でも衝突は毎回解決する。
判断の頻度は 10Hz で、動物の反応速度として不自然ではない。保持した餌の参照は、餌配列を詰め直すたびに付け替える。

### 2.3 近傍探索

視覚は「5つの扇形それぞれで最も近いもの」だけが必要なので、セルを近い順(リング状)にたどり、
- すべての扇形がまだ見ていない領域より近いものを見つけた、または
- 一定数(生き物 32、餌 56)を調べた
時点で打ち切る。混雑していても 1 個体あたりのコストがほぼ一定になる。

### 2.4 エネルギー保存

世界の総エネルギーは一定で、置き場所は「土」「植物」「肉」「生き物の体内」の4つだけ。

- 代謝・移動・噛みつきで使ったエネルギー、消化できなかった分 → 土
- 土 → 植物(肥沃度マップに従って発生。速度は土の量 × 季節係数に比例)
- 死亡 → 体内のエネルギーが肉片になる → 食べられるか腐って土へ

人口の上限は総エネルギーで自然に決まる。浮動小数点の誤差は 900 tick ごとに土の量で補正する。

### 2.5 脳

固定サイズの再帰型ネットワーク(入力 36、隠れ 16、出力 7)。結合はリストで持ち、隠れ層宛てを先、出力宛てを後に並べる。
隠れ層は前 tick の隠れ層の値を入力にでき(短期記憶)、出力層は同じ tick の隠れ層の値を使う。
突然変異は重みの変化、結合の追加・削除、バイアスの変化。結合数に比例した維持コストが不要な結合を淘汰する。

### 2.6 種

子と、その種の創始者との距離(遺伝子の重み付き差 + 脳の重みの差)がしきい値を超えると新種になる。
8 個体に達した種だけを「確立した種」として系統樹とイベントログに出す。

## 3. 検証の仕組み

| コマンド | 用途 |
|---|---|
| `hakoniwa-cli run` | 長時間の進化。統計を表示し、CSV と世界を保存 |
| `hakoniwa-cli bench --profile` | 段階ごとの処理時間 |
| `hakoniwa-cli assay --load W` | 採餌能力の比較(下記) |
| `hakoniwa-cli sweep --seeds 1,2,3` | 複数シードで受け入れ基準をまとめて判定 |

**採餌アッセイ**: 生態系全体の統計は、平衡状態では「摂取量 = 代謝量」になるため、採餌が上手くなっても数字に出ない。
そこで、代謝・老化・繁殖・捕食を止め、植物の密度を一定に保った同一の試験場に個体を置き、
2分間に集めた植物の量を第0世代と進化後で比べる。
